# v4 — Accessibility & i18n polish

The `a11y-i18n` slice makes the v4 workspace usable with a keyboard, a screen
reader, a reduced-motion preference, or a right-to-left locale. It is a
data-only backend plus a typed React panel; nothing in the slice executes user
code, reads files, or performs network calls from the domain layer.

## Layout

| Path | Responsibility |

## Contracts

`AuditRule` carries a `RuleId`, a description, an `AuditSeverity`, and an
`enabled` flag. `AuditIssue` records the rule, target element, detail, and a
concrete suggestion; `fingerprint` is a stable `rule:target` key used by the UI
for React list identity and de-duplication. `UiDescriptor` describes a rendered
element through role, accessible name, focusability, visibility, contrast ratio,
and tab index. Roles such as `h1`–`h6` expose `heading_level`; interactive roles
expose `interactive`.

`LocaleCatalog` pairs a locale tag (`en`, `fr`, `ar`, `en-GB`) with a `Direction`
and a table of `MessageId` → translated template. `PluralForms` supplies
category variants (`zero`, `one`, `two`, `few`, `many`, `other`) with `other` as
the universal fallback. `MotionPolicy` maps duration keys (`fast`, `normal`,
`slow`, `pulse`) to non-negative millisecond values. `TourStep` and
`EmptyStateSpec` hold onboarding copy. All structures validate at construction
and implement `to_dict()`/`from_dict()`.

## Audit rules

`A11yAuditor` runs five deterministic rules over a sequence of `UiDescriptor`
values:

1. `missing-label` — labeled roles with an empty accessible name (error).
2. `unfocusable-interactive` — interactive roles that are not focusable (error).
3. `low-contrast` — visible elements below the 4.5:1 AA threshold (warning).
4. `duplicate-id` — element ids that occur more than once (warning).
5. `skipped-heading-level` — heading jumps greater than one level (info).

`audit()` returns an `AuditReport` with ordered issues, the rules that ran, and
the descriptor count. `audit_issues()` returns just the issue list. Rules can be
disabled with `set_enabled()`; custom rule sets and severities are supported.
Issues sort by descending severity and then fingerprint, which keeps the UI
order stable across runs.

## Translation and formatting

`I18nCatalog` registers catalogs by locale. `translate()` resolves an exact
locale, then the language subtag, then the built-in English catalog; it replaces
`{placeholder}` tokens and reports unresolved names. `translate_plural()` uses
`plural_category(locale, count)` so Arabic gets six categories, French treats
0 and 1 as singular, and Japanese/Chinese always use `other`. Missing messages
fall back per message, and `TranslationResult` records both the resolved locale
and whether fallback occurred.

`LocaleFormatter` uses a static `FormatProfile` table instead of runtime locale
data. It groups numbers (`1,234,567` vs `1.234.567`), orders date fields
(`mdy`, `dmy`, `ymd`), and formats percentages and durations. Output is fully
deterministic for a given locale and input.

## Motion and tours

`MotionPolicyResolver.resolve()` maps `full`, `subtle`, or `off` to a duration
table. A `reduce_motion` flag forces `off`; `strictest()` picks the more
restrictive of two preferences; `css_variables()` converts a policy to
`--v4-duration-*` declarations. `TourEngine` keeps an index, status, and visit
history, supporting `start`, `next`, `previous`, `go_to`, `skip`, `complete`,
and `reset`. Advancing past the last step completes the tour; finished tours
reject further navigation.

## Storage

`PreferenceSnapshotStore` saves named captures of `Preferences`, a
`MotionPolicy`, and a locale. Names allow letters, digits, spaces, dots, dashes,
and underscores. Saves are versioned, timestamps come from an injected
`Clock`, and duplicates require `overwrite=True`. The store exposes `load`,
`get`, `remove`, `rename`, `revision`, `names`, `index`, `export`, and
`import_from`. `CatalogIndex` stores catalog metadata and a SHA-256 checksum of
translated messages so drift can be detected with `changed()`. `export_bundle()`
combines both stores into one JSON-serializable document.

## API

`register_endpoint()` mounts `/api/v4/accessibility` on a `RouteRegistry`;
`register()` supports registries, registrar objects, and mutable mappings. The
endpoint answers `GET` (requires `Capability.READ`) and `PATCH` (requires
`Capability.WRITE`; snapshot deletion additionally requires `DELETE`). Both
verbs require the `A11Y_I18N` feature flag. Every reply is an `ok()` envelope
with a deterministic `PageMeta` request id, or a `fail()` envelope carrying a
stable `ErrorCode`.

PATCH actions are `preferences`, `motion`, `reset`, `snapshot-save`,
`snapshot-load`, `snapshot-delete`, `tour`, `audit`, and `translate`. Duplicate
snapshots return `conflict`, missing snapshots return `not_found`, and invalid
input returns `invalid_input`. Preference mutations publish a
`PREFERENCE_CHANGED` event whose payload is filtered through `SAFE_EVENT_KEYS`
and the shared redactor before reaching the bus and outbox.

## Frontend

`AccessibilityClient` wraps the v4 `V4Client` and unwraps envelopes into typed
views; `AccessibilityClientError` preserves API error codes and details.
`accessibilityReducer` manages hydration, display controls, audit issues, tour
state, snapshots, busy/error flags, dirty state, and tab selection. Selectors
cover severity sorting/counts, motion labels, direction inference, progress,
and snapshot-name validation.

`AccessibilityPanel.tsx` renders a tabbed panel with four areas: display
controls (theme, density, motion, language, toggles, apply), an audit issue
list with severity badges and suggestions, an onboarding tour viewer with
progress and navigation, and snapshot save/load cards. It uses semantic
`fieldset`, `tablist`, `progressbar`, `alert`, and `aria-live` attributes so the
panel is usable without a pointer. `a11y-i18n.css` imports `tokens-v4.css` and
uses only `var(--v4-*)` tokens, including reduced-motion media queries.

## Testing

- `pytest tests/v4_a11y_i18n` covers every contract, all five audit rules in
  positive and negative cases, interpolation/fallback/plurals, locale
  formatting, motion resolution, tour flow, both storage adapters, and API
  envelopes/errors/events.
- `npm test` includes `v4-a11y-i18n.test.ts`, which exercises the reducer and
  selectors and verifies the client against injected `fetch` doubles.
