# V3 Accessibility, i18n, and Theme Refinement (B12)

B12 unifies the V2 accessibility, localization, theme, and motion work into one
verified V3 experience. It is additive: every V2 contract remains authoritative
and every B00 V3 contract is reused, never redefined.

## 1. Scope and invariants

- Offline-first: no remote requests, no telemetry, no external assets.
- No code execution: keyboard maps, catalogs, and layouts are data only.
- No new runtime dependencies: Python standard library plus existing V2 helpers.
- Shared files are untouched: no edits to B00 contracts, `main.tsx`, scripts,
  master plan, or V2 a11y code.

## 2. Backend layout

```
src/redscribe/v3/a11y_refinement/
  models.py               typed contracts for every refinement artifact
  wcag22_rules.py         deterministic WCAG 2.2 rule catalog and audits
  contrast_automation.py  target discovery, measurement, minimal repairs
  formatting.py           locale-aware formatting + additional catalogs
  rtl_layout.py           per-pane direction, mirroring, and CSS metadata
  keyboard_map.py         complete keyboard export from V2 + V3 bindings
  preferences.py          synchronized preferences + unified appearance
  service.py              A11yRefinementService facade
src/redscribe/v3/namespaces/a11y.py   dynamic V3 routes
```

The namespace is discovered by `V3Router.install_namespaces()` and registers
every route with `router.add("a11y", action, handler)`.

## 3. WCAG 2.2 audit rules

Fourteen deterministic rules are registered as data (`WCAG22_RULES`), including
the criteria new in WCAG 2.2:

| Rule | Criterion | Level | Check |
| --- | --- | --- | --- |
| `focus.not_obscured` | 2.4.11 | AA | Focused control is not fully hidden |
| `focus.not_obscured.enhanced` | 2.4.12 | AAA | No part of focus is hidden |
| `focus.appearance` | 2.4.13 | AAA | Indicator width and contrast |
| `pointer.dragging` | 2.5.7 | AA | Drag has a single-pointer alternative |
| `pointer.target_size` | 2.5.8 | AA | Targets at least 24px |
| `help.consistent` | 3.2.6 | A | Help in a consistent location |
| `form.redundant_entry` | 3.3.7 | A | No repeated data entry |
| `auth.accessible` | 3.3.8 | AA | No cognitive function test |

`SurfaceSpec` describes each V3 surface declaratively; `audit_surface()` and
`audit_surfaces()` produce `AuditRun` reports with stable rule IDs, severity,
WCAG criterion, remediation, and a deterministic score. `rules_for_level()`
filters the catalog by conformance target. All V3 surfaces are registered in
`DEFAULT_SURFACES` and audited by the `audit_all` route.

## 4. Contrast automation

`contrast_automation` delegates color math to V2 `contrast.py` and adds:

- `standard_targets()` — the light/dark token pairs used by design system v3;
- `targets_from_theme()` / `targets_from_payload()` — dynamic target discovery;
- `auto_fix()` — the nearest passing foreground or background, chosen by RGB
  distance so the visual change stays minimal;
- `automate()` — batch evaluation, failures, fixes, suggestions, and score;
- `dual_theme_report()` — light/dark equivalence with normalized pair names.

Required ratios follow the context: 4.5:1 for body text, 3:1 for large text and
graphics, 7:1 for AAA body text.

## 5. Locale-aware formatting and catalogs

`formatting` composes V2 formatters for number, percent, currency, bytes, date,
time, datetime, relative time, plural, ordinal, duration, range, and list.
Each `FormatResult` carries its resolved direction and a bidi-isolation hint.

Six additional catalogs are registered as data: `pt-BR`, `it`, `nl`, `ko`, `fa`,
and `ur`. They add V3 keys (`v3.audit.*`, `v3.search.results`, `v3.keyboard.*`,
and others) and fall back through the V2 locale chain to English. `round_trip()`
verifies that a localized number parses back to its source value;
`catalog_report()` exposes per-locale coverage.

## 6. RTL layout metadata

`rtl_layout` describes twelve panes with logical regions, mirrored icon lists,
and CSS custom properties. `layout_for()` maps logical `start`/`end` to physical
sides using the V2 RTL helpers, reverses region order for RTL without changing
DOM structure, and reports bidirectional text hazards. `validate_layout()`
asserts that direction, sides, and CSS class stay consistent; `document_attributes()`
returns the `lang`/`dir` pair required on a surface root.

## 7. Complete keyboard map

`keyboard_map` extends the V2 registry with 18 V3 bindings: twelve surface
navigation actions, next/previous pane, RTL and motion toggles, high contrast,
and status announcements. `export_keyboard_map()` validates conflicts, groups
bindings, formats each binding for desktop/mac/web, and marks the map complete
only when every action is present and conflict-free. `help_lines()` localizes
the export and `focus_sequence()` produces the tab order used by the keyboard
pass UI. Unknown punctuation keys inherited from V2 defaults (for example the
commas in `Ctrl+,`) are accepted; genuinely unknown override keys become
conflicts.

## 8. Preference synchronization

`PreferenceSyncService` wraps V2 preference validation with versioned
`PreferenceSyncRecord`s and stable checksums. Four strategies are supported:
`local_wins`, `remote_wins`, `merge`, and `reject`. `merge` combines shortcut
maps, flags simultaneous edits of the same field, and returns a `SyncReport`
with changes, conflicts, and warnings.

`UnifiedAppearance` is the single theme/motion control: theme, motion mode
(`full`/`reduced`/`off`), density, direction, font scale, high contrast, and
focus-ring boost. Motion mode survives snapshot round-trips through a data-only
marker in the shortcut map; `appearance_css()` renders all of it as V3 custom
properties. Reduced and off modes disable transitions without hiding content
or changing focus order.

## 9. V3 API routes

| Action | Purpose |
| --- | --- |
| `health`, `rules`, `surfaces` | namespace metadata |
| `audit`, `audit_all` | single-surface and full audits |
| `contrast`, `theme_contrast` | automated pairs and dual-theme comparison |
| `format`, `format_batch`, `round_trip`, `translate`, `locales` | i18n |
| `rtl`, `rtl_manifest`, `bidi` | layout metadata |
| `keyboard`, `keyboard_help`, `keyboard_lookup`, `keyboard_group` | keyboard pass |
| `preferences`, `preferences_update`, `preferences_sync`, `motion` | sync + appearance |
| `dashboard`, `export` | combined views and portable metadata |

Handlers return the data portion of the standard B00 `{ data, meta }` envelope;
validation errors use stable `V3ErrorCode` values (`INVALID_TYPE`,
`INVALID_CHOICE`, `INVALID_REQUEST`, `CONFLICT`).

## 10. Frontend feature

`frontend/src/features/a11y-refinement/` contains pure helpers (`wcag.ts`,
`contrast.ts`, `format.ts`, `catalogs.ts`, `rtl.ts`, `keyboard.ts`,
`preferences.ts`), a typed `V3Client` wrapper, and components:

- `A11yRefinementPanel` — audit, contrast, keyboard, and locale summary;
- `KeyboardPassList` — tab/arrow navigable binding groups with `<kbd>` labels;
- `FocusOrderView` — explicit tab sequence and focus findings;
- `RtlLayoutPane` — mirrored regions with logical CSS sides;
- `LocaleCatalogPicker` — locale, direction, and catalog coverage;
- `UnifiedAppearanceControl` — one theme/motion/density control;
- `ScreenReaderLabel` — visually hidden labels, live regions, and announcers.

All controls expose `aria-*` names, native keyboard activation, visible
`:focus-visible` outlines using `--v3-focus`, and reduced-motion fallbacks.
Styles live in `a11y-refinement.css` and consume only B00 design tokens.

## 11. Tests and quality gates

- Python: `tests/v3_a11y_refinement/` covers models, rules, contrast, formatting,
  RTL, keyboard, preferences, and namespace routes.
- Frontend: `frontend/scripts/a11y-refinement-v3.test.ts` is registered through
  `frontend/scripts/test-suites/12.json` and exercises the pure helpers.
- Gates: ruff check/format, mypy strict, pytest, `REDSCRIBE_SKIP_TYPECHECK=1
  npm test`, and the LOC gate against `c65e699`.

## 12. Exit criteria

No new V3 surface fails the WCAG 2.2 audit; both themes and RTL pass contrast
and keyboard checks. Every locale catalog resolves with fallback, every pane
has direction metadata, and preferences synchronize without losing user intent.
