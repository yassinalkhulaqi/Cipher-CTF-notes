# V2 Accessibility, i18n, and Themes

This branch adds an additive `a11y.*` V2 namespace, a frontend accessibility panel, locale and theme tooling, and persisted user preferences. It does not change the shared V2 platform kernel routes.

## Backend namespace

The namespace is implemented in `src/redscribe/ui/web/v2/namespaces/a11y.py` and backed by `A11yService` in `src/redscribe/v2/a11y/service.py`.

Route families:

- `a11y.audit`, `a11y.focus`, `a11y.aria`, `a11y.roles` for structural audits.
- `a11y.contrast`, `a11y.contrast_check` for WCAG contrast checks.
- `a11y.locales`, `a11y.locale_detail`, `a11y.catalog`, `a11y.translate`, `a11y.coverage`, `a11y.format`, `a11y.rtl` for internationalization.
- `a11y.themes`, `a11y.theme_detail`, `a11y.theme_create`, `a11y.theme_css`, `a11y.theme_compare`, `a11y.theme_contrast`, `a11y.theme_fixes` for theme validation and CSS generation.
- `a11y.shortcuts`, `a11y.shortcut_format` for keyboard shortcut normalization and conflict detection.
- `a11y.preferences*`, `a11y.dashboard`, `a11y.health` for persisted settings and combined reporting.

Registration is additive through `register_with_service(service)`. Existing `ApiV2` registration falls back to the internal `_register` hook, so no shared V2 route file needs editing.

## Service modules

- `models.py` defines shared records, `ElementNode`, `WcagLevel`, `ThemeDefinition`, and preference snapshots.
- `contrast.py` handles color parsing, relative luminance, WCAG ratios, palettes, and token-combination validation.
- `aria.py` validates roles, ARIA attributes, and accessible names.
- `focus.py` analyzes focus order, tabindex heuristics, skip links, and focus modes.
- `shortcuts.py` parses bindings, detects conflicts, and groups shortcuts by context.
- `themes.py` and `theme_contrast.py` define themes, token validation, CSS variables, and contrast fixes.
- `preferences.py` validates, merges, signs, and stores user preference records.
- `i18n/` holds locale metadata, catalogs, formatters, and RTL helpers.

Contrast input accepts either `pairs` as a list of mappings or a named `palette`. WCAG levels may be supplied as strings such as `"aa"`; they are coerced to `WcagLevel`.

## Frontend feature

The React feature lives in `frontend/src/features/a11y/`:

- `client.ts` wraps `V2Client` and maps each facade method to a `a11y.*` route.
- `pure.ts` contains deterministic helpers for locale tags, direction, contrast grades, issue ordering, shortcut bindings, CSS variables, preference merging, bidi text, and announcements.
- `store.ts` is a zustand store for panel state, preferences, reports, and announcements.
- `hooks/` applies preference CSS variables to the document root, loads dashboard data, announces state changes, and scans focus order from a DOM root.
- `components/` renders the panel, theme and locale pickers, display controls, audit and contrast summaries, shortcut editor, focus order, and screen reader helper.
- `styles/a11y.css` is imported only by `components/A11yPanel.tsx`; it is not added to the shared stylesheet index.

Preferences are persisted locally under `redscribe.a11y.preferences.v2` and can be synchronized through `a11y.preferences_update`. The panel uses `aria-expanded`, `aria-controls`, labelled controls, a polite live region, and visible focus styles.

## Tests and gates

Python tests live in `tests/v2_a11y/`. Frontend tests live in `frontend/scripts/a11y_v2.test.ts` and are registered in `frontend/scripts/test.mjs`.

Run:

```bash
PYTHONPATH=src python3 -m pytest -q -p no:asyncio
python3 -m ruff check .
python3 -m ruff format --check .
PYTHONPATH=src python3 -m mypy src
cd frontend && npm test && npm run format:check && npm run typecheck && npm run build
python3 scripts/loc_gate.py --base origin/dev/v2-00-platform-kernel --min-added 4000 --min-tests 500
```

The feature is intentionally additive. Shared files such as `App.tsx`, `routes.ts`, the V2 namespace registration files, quality gate scripts, and workflow configuration are not modified.
